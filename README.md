# Bili Auto Uploader

Windows 视频自动上传客户端，当前版本 **1.0.2**。手动批量选择视频，按预设标题、分区和标签依次上传，每个视频单独自动投稿；可实时查看进度、速度和预计剩余时间。

[下载 Windows x64 便携版](https://github.com/lxDragonn/bili-auto-uploader/releases/latest)

## 使用

1. 解压 `BilibiliUploader-1.0.2-win-x64.zip`，双击 `BilibiliUploader.exe`。升级前退出旧版。便携包自带 .NET 运行时，无需安装开发工具。
2. 在“账号与创作中心”中登录 Bilibili 官方页面，然后点击“读取账号与分区”。客户端使用独立登录目录，不读取 Edge 中已有的 Cookie。
3. 在“投稿预设”中选择分区，填写标题模板、标签、简介和作品类型，然后保存。
4. 在“上传队列”中点击“添加视频”，可一次选择多个文件。点击“开始上传并投稿”，客户端按顺序完成上传和投稿。
5. “已投稿”表示服务器返回了稿件编号，转码、审核及最终可见状态需在创作中心查看。封面采用平台默认处理；本版没有自定义封面或合集功能。

支持 Windows 10/11 x64，无需管理员权限。若提示 WebView2 Runtime 缺失，请从 [Microsoft 官方页面](https://developer.microsoft.com/microsoft-edge/webview2/)安装 Evergreen Runtime。

## 投稿预设

| 设置 | 作用 |
| --- | --- |
| 标题模板 | 使用下表中的变量生成每个视频的标题，展开后最多 80 个字符 |
| 分区 | 登录后从 Bilibili 读取并选择具体子分区 |
| 标签 | 用中文或英文逗号分隔，1–10 个，每个最多 20 字符 |
| 简介 | 当前批次共用，最多 2000 个字符 |
| 作品类型 / 来源 | 原创或转载；转载需填写来源 |
| 分片重试 | 0–5 次；临时网络故障或部分服务器错误可重试同一分片 |

| 标题变量 | 含义 |
| --- | --- |
| `{filename}` | 不含扩展名的完整文件名 |
| `{title}` | 去除有效录像时间前缀后的标题 |
| `{index}` | 当前队列中的序号，从 1 开始；保留在队列内的已完成任务也计入 |
| `{record_date}` | 从文件名提取的录像日期，如 `2024-01-02` |
| `{record_date:yyyy.M.d}` | 录像日期，月日不补零，如 `2024.1.2` |
| `{date}` | 开始上传当天的本地日期，如 `2024-01-02` |
| `{date:yyyy.M.d}` | 上传日期，月日不补零，如 `2024.1.2` |

点击“使用直播回放模板”，或填入：

```text
【直播回放{record_date:yyyy.M.d}】{title}
```

虚构示例文件 `20240102-120000-123-示例录像.flv` 会展开为：

```text
【直播回放2024.1.2】示例录像
```

支持的时间前缀为 `yyyyMMdd-HHmmss-fff-`（年月日、时分秒、三位毫秒），且必须为有效日期时间。隔天上传仍使用录像日期；标题中的中文、英文、数字、标点和连字符均保留。

不符合命名格式时，`{title}` 保留完整文件名（去除扩展名），`{record_date}` 提示无法读取录像日期。可直接填写实际日期，或使用 `{date:yyyy.M.d}` 表示上传日期。无效或未写完整的模板在预览中提示，选择其他视频会更新预览。

点击开始时固定本批次预设。运行期间暂时禁用账号切换和预设修改。文件必须已经录制完成；开始前核对大小和修改时间，上传期间保持只读文件锁。

## 进度与任务恢复

- 进度来自实际写入上传连接的视频字节，同时显示服务端已确认的分片字节。失败重试不重复累计确认进度，重试时进度可能回退。
- 速度为最近约 3 秒传出的正文流量，包含重传；剩余时间不包含服务器合并、投稿和审核耗时。
- **暂停**：完成当前分片后暂停，点击继续恢复；已提交的投稿请求不能撤回。
- **停止 / 退出**：取消传输并停止后续任务。已上传但未投稿的文件保留远端标识；未传完的视频下次重新上传。本版不支持退出后的分片断点续传。
- **待核对**：投稿请求已发出，但响应丢失或程序中断。客户端不会自动重发；先在创作中心确认，再用“核对所选结果”标记成功或允许再次提交。
- 登录失效、验证码、风控、投稿限制和接口错误会中止当前队列，处理后再开始。

## 数据与网络

队列、预设和独立登录资料保存在 `%LOCALAPPDATA%\BilibiliUploader`，详情见 [隐私说明](PRIVACY.md)。公开源码和便携包不附带用户队列、Cookie、登录资料、录像、日志或账号信息。

视频仅传给 Bilibili 返回且通过校验的 HTTPS `*.bilivideo.com` 地址，上传客户端禁止重定向。账号及投稿请求使用官方 `member.bilibili.com` 页面中的登录状态。应用自身没有遥测、第三方网盘或自动更新服务。

## 验证与限制

测试覆盖文件流、分片内容一致性、重试去重、暂停、取消、错误中止、顺序投稿、标题日期提取、无效模板、上传域名限制、崩溃恢复及投稿结果不明处理。还覆盖带零小数部分的上传编号、长整数精度、无效编号与异常接口响应；本机 HTTP 测试验证实际传输的数据与源文件一致。

Bilibili 内部上传接口可能变化，不同账号、分区、格式和风控条件可能影响上传。投稿成功不等于审核通过，最终转码、审核和可见状态由平台决定。客户端使用独立实现的分片传输，未复制 Bilibili 上传库。

协议核对来源：[官方视频投稿页](https://member.bilibili.com/video/upload.html)、[Microsoft WebView2 安全建议](https://learn.microsoft.com/microsoft-edge/webview2/concepts/security)。

## 开发与构建

需要 Windows 和 .NET 8 SDK。

```powershell
dotnet run --project tests/Uploader.Tests.csproj -c Release
pwsh -File ./publish.ps1
```

构建脚本在 `artifacts/` 输出便携 EXE、压缩包、第三方许可和 SHA-256。项目使用确定性构建，将项目路径映射为 `/_/src`，不生成调试符号。便携包固定 .NET 8.0.31 和 WebView2 SDK 1.0.4258.31；WebView2 浏览器运行时由系统独立更新。没有安装器、开机启动项或后台服务。

项目尚未指定开源许可证；第三方组件的许可随便携包单独附带。
